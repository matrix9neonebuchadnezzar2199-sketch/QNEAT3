GUI NO_PATH の原因特定（座標 CRS 誤解釈）と UX 修正、実機完走

incident tool 14:24 pending

背景

ローカル QGIS 3.40.9（この端末に新規導入）で最短経路を実行すると NO_PATH。 デバッグ計装（7 箇所＋プローブ 2 箇所、NDJSON ログ）で追跡したところ、 当初の「方向フィールド自動入力」仮説は交絡変数で、真因は CRS 接尾辞なしの座標がレイヤ CRS（EPSG:6677、メートル）として解釈されることだった。

原因

層内容
真因 GUI で 138.920116,35.111750 と CRS 指定なしで入力 → プロジェクト CRS（EPSG:6677）のメートルとして解釈 → 両点が ~123 km 離れた 同一の誤頂点に結線（計装ログ: tied_start == tied_end）→ 始点=終点で NO_PATH。 成功時との対比で「座標が変換されず度のまま」であることがログで確定
交絡変数 方向フィールド NODE1 の自動入力。初回再現で success との差分と誤認したが、 プローブで directedAnalysis=false / field_id=-1（常に無視）と判明。 教訓: A/B 比較は変数を 1 つだけ変える（自分の再現コマンドが CRS 接尾辞も落としていた）
関連の既知事項 元ネットワークに link_len 無し → 検証が ~2 秒で例外（「10 秒で完了・表示なし」の正体）…… 前処理で作成が正規手順（昨日確定済み）

対応（UX 修正）

度の範囲の座標を検出（投影 CRS レイヤ） → 経緯度とみなして自動変換＋明示ログ → 同一頂点結線は専用エラー（CRS 案内つき） → 接尾辞なしでも 146,542 m で完走
  • _coerce_lonlat_point: 投影 CRS レイヤで |x|≤180, |y|≤90 の点を経緯度とみなして変換（LOG.POINT_ASSUMED_LONLAT で明示。接尾辞での明示指定も従来通り有効）
  • ERR.SAME_TIE_VERTEX: 始点=終点の同一頂点結線を汎用 NO_PATH から専用エラー化（CRS 案内つき）
  • LOG.TIE_FAR_WARNING: 点がネットワークから 100 km 超の接続で警告
  • 方向フィールドのガード: 照合値が空ならフィールド指定を無視（自動入力の罠対策。upstream 由来の潜在問題）

変更ファイル

  • M algs/ShortestPathBetweenPoints.py（経緯度みなし変換・同一頂点チェック・遠距離警告）
  • M Qneat3Framework.py（方向フィールドガード・None 正規化）
  • M Qneat3Strings.py（ERR.SAME_TIE_VERTEX / LOG.TIE_FAR_WARNING / LOG.POINT_ASSUMED_LONLAT）
