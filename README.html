導入方法（初心者向け）

重要: Python の import 名は QNEAT3 です。コピー先フォルダ名も QNEAT3 にしてください（QNEAT3_NEO のままだと読み込めません）。
ZIP を入手 → フォルダ名を QNEAT3 に → plugins に配置 → QGIS で有効化
  1. QGIS 3 をインストール
    公式サイト qgis.org から「長期リリース版（LTR）」を推奨。インストール後、一度 QGIS を起動して終了しておく。
  2. プラグインフォルダを開く
    QGIS メニュー: 設定 → ユーザープロファイル → プロファイルフォルダを開く
    開いたエクスプローラーで python\plugins に移動する。 
    例（Windows）:
%APPDATA%\QGIS\QGIS3\profiles\default\python\plugins\
  3. プラグインをコピー
    リポジトリの QNEAT3_NEO フォルダの中身すべてを、上記 plugins\QNEAT3 として配置する（新規フォルダ作成）。 
    plugins\
  └── QNEAT3\          ← この名前が必須
        ├── __init__.py
        ├── Qneat3Plugin.py
        ├── algs\
        ├── icons\
        └── …
  4. QGIS を再起動
    完全に終了してから起動し直す。
  5. プラグインを有効化
    メニュー プラグイン → プラグインの管理とインストール → インストール済み で「QNEAT3」を検索 → チェックを入れる。
  6. 動作確認
    メニュー プロセス → プロセスツールボックス を開き、検索欄に QNEAT3 と入力。グループ「QNEAT3 - QGIS ネットワーク解析ツールボックス」が表示されれば成功。

等時圏ポリゴン・等値線を使う場合（任意）

一部アルゴリズムは matplotlib が必要です。OSGeo4W Shell で:

python-qgis -m pip install matplotlib

インストール後、再度 QGIS を再起動してください。

実行前のデータ準備

項目内容
ネットワークレイヤ 道路・管路などの線レイヤ。トポロジがつながっていること。
link_len 数値フィールド。距離最適化時は全リンク必須（正の数、NULL 不可）。形状長と異なる「論理距離」を入れる。
速度フィールド 時間最適化時に使用（km/h）。未設定時はデフォルト速度。
座標系 メートル単位の投影 CRS（例: 平面直角座標）。WGS84 地理座標のまま距離解析は非推奨。

基本的な使い方

  1. 線ネットワークレイヤを読み込む（link_len を付与済みであること）。
  2. プロセスツールボックスで例: 最短経路（点間） を開く。
  3. 最適化基準で「最短経路（距離）」または「最速経路（時間）」を選択。
  4. 高度パラメータで リンク長フィールド = link_len（距離モード時）。
  5. 実行。ログに コストモード: … が出るので戦略を確認。

始点・終点の座標入力（NEO 1.0.24）

入力方法扱い
138.920116,35.111750 のように度の範囲の数値 投影 CRS のレイヤでは経緯度 (EPSG:4326) とみなして自動変換されます（ログに明示）。そのまま入力して構いません
138.920116,35.111750 [EPSG:4326] のように CRS 接尾辞つき 指定 CRS からレイヤ CRS に変換（最も明示的・推奨）
地図キャンバスをクリック プロジェクト CRS の座標として取得（レイヤと同じ CRS の地図なら問題なし）
OD 行列のポイントレイヤ レイヤの CRS からネットワーク CRS へ自動変換されます（1.0.25、ログに明示）。同一頂点に結線した別点ペアは「到達不能」ではなく network_cost=0 + entry/exit になります
CRS 指定を誤ると: 両点が遠く離れた同一頂点に結線され「始点と終点が同じネットワーク頂点に結線されました」というエラーになります （以前は汎用の「経路が見つかりません」でした）。座標の形式を見直してください。
更新確認は下記 検証手順（STEPS） を参照してください。

検証手順（STEPS）

プラグイン更新の反映確認、link_len による距離コストの動作確認、 「実測距離のままに見える」問題の切り分け用です。作業前に QGIS を完全終了し、 plugins\QNEAT3 を最新版に差し替えてから再起動してください。

A. プラグイン更新の反映確認

  1. QGIS を終了し、…\profiles\…\python\plugins\QNEAT3 を最新の NEO 版に上書きする。
  2. QGIS を起動し、処理 → ツールボックス を開く。
  3. プロバイダ一覧で名前が QNEAT3 (1.0.24, 20260806-lonlat-crs) のように バージョンとビルド ID 付きになっていることを確認する。
    古い表示の場合は、別フォルダのプラグインが読み込まれている可能性があります（QGIS 未再起動で metadata だけ新しく読まれる混在表示もありえます）。
  4. 任意のアルゴリズム（例: 最短経路（点間））を実行し、ログに コストモード: 最短距離（link_len 属性） または時間モードの表示が出ることを確認する。

B. link_len 距離コストの動作確認

  1. 線ネットワークに link_len フィールド（全リンク正の数値）を用意する。 テスト用に数リンクだけ形状長と意図的に異なる値を入れると判別しやすいです。
  2. 最短経路（点間） を開き、最適化基準を 「最短経路（距離最適化）」に設定する。
  3. 高度パラメータを開き、リンク長フィールド = link_len を指定する。
  4. 実行し、ログで次を確認する。
    ログ項目期待
    コストモード 最短距離（link_len 属性）
    距離最適化: 速度フィールド… 距離モードで速度が無視される旨（デフォルト速度 0 でも可）
  5. 出力属性を分けて確認する。
    • cost_on_graph … グラフ上（link_len の合計）
    • start_entry_cost / end_exit_cost … ネットワーク外の実測接続距離（仕様）
    • total_cost … 上記の合計（entry/exit が大きいと実測寄りに見える）
    ログに [QNEAT3] コスト値: entry=… graph=… exit=… total=… も出ます。

C. 時間最適化との切り替え確認

  1. 同じダイアログで 最適化基準だけ「最速経路（時間最適化）」に変更する。
    パラメータ一覧の項目数・ラベルは変わりません（Processing の仕様）。
  2. 再実行し、ログで コストモード: 最速（link_len ÷ 速度。形状長は未使用） になることを確認する。
  3. [QNEAT3] UI 注記 が出ていれば、距離時は link_len・時間時は速度フィールドが有効である旨の説明です。
link_len が形状長と同じ値の場合
データ上 link_len が形状長と同じ値のため、距離最適化でも結果が変わらないように見えます。フィールド値を見直してください。
最適化基準を変えてもパラメータ一覧は変わりません（仕様）
実際のモードはログの コストモード と 検証手順 B/C で確認してください。

最短距離と最短時間が「同じ」ように見える場合

結論（コード調査）: 距離と時間で同じ戦略が強制されるバグは見つかっていません。 グラフ構築時に Qneat3LinkLengthStrategy（link_len）と Qneat3LinkLengthTimeStrategy（link_len÷速度）を切り替えています。式一覧は COST_FORMULAS.md。
モードエッジコストentry / exit
最短経路（距離） link_len の値 点↔頂点の直線距離（楕円体 or 平面）
最速経路（時間） link_len ÷ 速度（km/h→m/s 換算） 実測直線距離 ÷ 速度

同じ「経路形状」になるのは正常なことが多い

全リンクの速度が一定のとき、コストは「距離 × 定数」となり、どの経路が最短かの順序は距離モードと一致します。表示される total_cost の数値は通常異なります。

コストまで同じに見えるときのチェックリスト

  • 本当に「最適化基準」を切り替えたか（ログの コストモード を確認）
  • link_len を「形状長 ÷ 速度」で事前計算していないか
  • 速度が一定で、かつ entry コストが支配的でないか
  • 比較しているのが経路ジオメトリだけではないか（属性の cost_on_graph を比較）

架空道路を追加して計算する（NEO 1.0.23）

例: 東京〜御殿場を計算すると通常は東名高速が選ばれるところを、 架空の道路を描き足してそちらを通らせたい場合の手順です。

なぜ描いただけでは通らないのか
QGIS のネットワーク解析は、リンクの端点同士が一致する場所にしか接続を作りません。 道路の途中に突き当たる新規リンクや、端点がわずかにズレたリンクは、 グラフ上で孤立し、エラー無しで静かに無視されます（既存の高速道路が選ばれます）。

手順（描く → 前処理 → 計算）

  1. 既存ネットワークと架空道路を 1 つの線レイヤにまとめる。 接続したい場所には、架空道路の端点で突き当てる （途中×途中の交差は接続になりません＝立体交差扱い）。
  2. プロセスツールボックスで [NEO] ネットワーク前処理（接続・link_len） を実行。
    • 他リンクの途中に近い端点 → そのリンクを分割してノード挿入＋端点吸着
    • 端点のズレ → 許容差内で完全一致（スナップ）
    • 未入力の link_len → 実測長で補完（既定 ON）
    • 分割したリンクの link_len → 実測長の比率で按分（合計は保存）
    • ログに 連結成分数 と孤立リンク警告が出ます。1 成分なら全リンク到達可能です。
  3. 出力された「前処理済みネットワーク」を、最短経路・OD 行列・等時圏の ネットワークレイヤに指定して計算する。
経路が架空道路を通る条件
経路選択は最小コストで決まります。通らせたい架空道路は link_len を既存ルートより短めに（時間最適化なら速度を高めに）設定してください。 コスト的に不利な道路は（正しく）選ばれません。

出力ラインの形状: QGIS のグラフはポリラインをセグメント（頂点→頂点）ごとの辺に分割するため、 経路の頂点チェーンは通過リンクの実形状と厳密に一致します （曲線で描いた架空道路も曲線のまま描画）。コスト計算は link_len 系のみです。

重要（1.0.23 で修正）: セグメントごとの辺にフィーチャ全体の link_len を課金する設計ミスで、 セグメント数の多いリンクを通るとコストが数倍に膨らんでいました（例: 東京〜御殿場が ~945 km と表示）。 現在は link_len × (セグメント長 / リンク全長) で按分され、Σ が厳密に link_len と一致します。

既知の挙動・バグ調査結果（NEO 1.0.10）

重要度内容状態
修正済 セグメント辺ごとに link_len 全額を課金 → 複数セグメントのリンクでコストが数倍に膨張（945 km 表示等） 1.0.23 で link_len × (d_seg / L_link) 按分に修正
修正済 座標を CRS 指定なしで入力 → レイヤ CRS（メートル）と誤解釈され、両点が同一の誤頂点に結線 → NO_PATH 1.0.24 で経緯度みなし変換＋同一頂点の専用エラー（CRS 案内つき）＋遠距離接続の警告
修正済 GUI が方向フィールドを自動入力し、空の照合値に空属性がマッチして一方通行化しうる 1.0.24 で照合値が未設定なら方向フィールドを無視するガード

「プラグインが壊れています」／再インストールで元に戻る

再インストールボタンは使わないでください。
プラグインマネージャから入れた QNEAT3 は、再インストール・アップグレード時に plugins.qgis.org の公式 1.0.8 を再取得し、NEO 版を上書きします。 これが「更新したのに元に戻る」「壊れたまま」の典型原因です。

原因の整理

症状よくある原因
属性情報の読み取りエラー: general metadata.txt 不正（空の homepage=、version=1.0.11-neo-…、tags の「, 」など）。NEO 1.0.11 で修正済み
インストール版が「?」 上記の metadata 読み取り失敗。ZIP を再取得して入れ直す
プラグインが壊れています（実行時） 読み込み例外（algs/__init__.py 欠落、混在、NEO_load_error.txt を確認）
再インストールで公式版に戻る マネージャが公式 ZIP を取得（NEO の metadata.txt で repository= を空にしても、過去に公式登録済みだと残ることがある）
ZIP 更新が反映されない QGIS キャッシュ（%LocalAppData%\QGIS\QGIS3\cache）や QGIS 未終了によるファイルロック

推奨: クリーン導入（NEO 版）

  1. QGIS を完全終了（タスクマネージャで qgis-bin.exe が無いことを確認）。
  2. プラグイン → プラグインの管理とインストール → インストール済みで QNEAT3 をアンインストール（公式登録を外す）。
  3. エクスプローラで …\python\plugins\QNEAT3 フォルダを丸ごと削除 （残っていると混在して壊れます）。
  4. NEO 版を配置する（どちらか一方）。
    • 手動: リポジトリの QNEAT3 フォルダを plugins\QNEAT3 にコピー
    • ZIP: scripts\pack_plugin_zip.ps1 で dist\QNEAT3-neo-….zip を作成し、 プラグイン → ZIP からインストール（公式の再インストールではない）
  5. QGIS 起動 → プラグイン一覧で QNEAT3 NEO を有効化。 壊れている場合は plugins\QNEAT3\NEO_load_error.txt の内容を確認。
NEO 版の目印: 一覧の表示名が QNEAT3 NEO、 処理プロバイダが QNEAT3 (1.0.24, 20260806-lonlat-crs) のようにバージョン付きであること。
